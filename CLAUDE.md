# coupled-tags-lint

`devbox run -- task check` runs ruff and the tests, then builds the flake and lints this repository's tags with the command it packages; run it before finishing. After changing a COUPLED group here, record it with `devbox run -- uv run coupled-tags-lint --update`; `.config/ianf-coupled-tags.toml` excludes the README and the tests. `devbox run -- task lint-file -- <files>` formats and fixes the Python files given.

The lint is a functional core (`core/`) with an orchestrator (`orchestrators/lint.py`) and adapters; test the core with plain values, and the command through `tests/test_cli.py`, which runs it as a program. The tag format is defined in coupled-tags (`~/projects/claude/coupled-tags`): its SKILL.md and README, this repository's `core/tags.py` and `core/comments.py`, and its gate hook, which imports them, change together. The lint doesn't read other repositories: a `//<git-host>/<owner>/<name>/<path>` file is checked only for its form and consistency, and listed as not checked. coupled-tags-cross-repo (`~/projects/cli/coupled-tags-cross-repo`) checks across repositories by importing `core/`: what it imports, such as `Tag.repos()`, `Tag.files()` and `compare` with its lock file and update instruction, is its API, as are the `GrepSearch` and `LocalFiles` adapters it wires, so changing them is a breaking change for it. A repository's settings file, `.config/ianf-coupled-tags.toml`, is read through repo-settings by the `LocalSettings` adapter and decided by `core/settings.py`; its format has a schema for each version in `schema/`, and a change an existing file doesn't meet makes a new version. Only that adapter imports repo-settings, so `core/` stays standard-library only for the gate hook. `flake.nix` packages the command for other projects' devbox, which pin a release tag, so a change reaches them only once it's released and they move to the new tag. The flake builds only files git tracks, so a new file needs `git add` before `task tags` sees it.
