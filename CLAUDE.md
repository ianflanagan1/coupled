# coupled

`devbox run -- task check` runs ruff and the tests, then builds the flake and lints this repository's markers with the command it packages; run it before finishing. After changing a COUPLED group here, record it with `devbox run -- uv run coupled --update <key>`; `.config/coupled.toml` excludes the README, the tests and `examples/`. `devbox run -- task lint-file -- <files>` formats and fixes the Python files given.

The lint is a functional core (`core/`) with orchestrators (`orchestrators/lint.py`, and `orchestrators/hook.py` for the Claude Code hooks) and adapters; test the core with plain values, and the commands through `tests/test_cli.py` and `tests/test_hook.py`, which run them as programs. The marker and registry format is defined in coupled-convention (`~/projects/claude/coupled-convention`): its SKILL.md and README, and this repository's `core/markers.py`, `core/relations.py`, `core/registry.py`, README and `examples/demo`, change together. Write examples of markers in `src/` with placeholders (`COUPLED:<key>: <label>`), or quoted as search text (`"COUPLED:upload-limit:"`), since a concrete one is a marker the lint checks.

`coupled-hook` (`adapters/driving/hook.py`) is the gate and context hook, registered in `~/.claude/settings.json` to run from this checkout's `.venv`, so a change to it takes effect for Claude at once. It runs on every Read, so `__main__.py` imports only what each entrypoint wires, and the settings adapter imports repo-settings only when a file holds markers.

The lint doesn't read other repositories: a `//<git-host>/<owner>/<name>/<path>` file is checked only for its form, and listed as not checked. coupled-tags-cross-repo (`~/projects/cli/coupled-tags-cross-repo`) is written against the old bracket-tag core and needs porting to the registry before it works with this version. A repository's settings file, `.config/coupled.toml`, is read through repo-settings by the `LocalSettings` adapter and decided by `core/settings.py`; its format has a schema for each version in `schema/`, and a change an existing file doesn't meet makes a new version. `flake.nix` packages the command for other projects' devbox, which pin a release tag, so a change reaches them only once it's released and they move to the new tag. The flake builds only files git tracks, so a new file needs `git add` before `task markers` sees it.

`examples/demo` is a small project using every form of marker and relation, kept clean by `tests/test_cli.py`. After changing it, record its groups with `devbox run -- uv run coupled --update <key> examples/demo`. `devbox run -- task copy-demo` copies it into a new git repository in a temporary directory, where the hooks and `--fix` work on it as on any project.
